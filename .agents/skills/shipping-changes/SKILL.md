# Как выкатывать изменения

## Ветка

Новая работа — новая ветка от свежего `main`:
`git switch main && git pull && git switch -c <тип>/<суть>`, например
`feat/garmin-1040-case` или `fix/540-charging-port`. Если задача продолжает
уже открытую ветку — работайте в ней. В `main` напрямую не коммитим.

## Коммиты

- **Одна атомарная правка — один коммит.** Новая модель, исправление посадки
  и документация — три коммита.
- **Одна строка, без тела**, в стиле Conventional Commits: `feat`, `fix`,
  `docs`, `chore`, `refactor`. Пишите, что правка даёт:
  `fix: widen the 540 charging port by 0.4 mm`, а не «правки в модели».
- **Никаких `Co-Authored-By` и подписей инструмента.** Хук
  (`.claude/settings.json` у Claude, `.codex/hooks.json` у Codex) отклоняет
  такой коммит.
- Файлы добавляйте прицельно (`git add <файлы>`), а не `git add -A`.
- STL идёт в одном коммите с `.blend`, из которого выгружен, и с отчётами
  проверок, если они поменялись.

## Тяжёлые файлы

STL и `.blend` здесь весят 30–70 МБ. GitHub предупреждает о файлах больше
50 МиБ и не принимает файлы больше 100 МиБ. Узнаётся это только на
`git push`, когда файл уже в истории и убрать его можно только перезаписью.

- Перед коммитом: `git diff --cached --stat` — у бинарных файлов там виден
  размер в байтах.
- `.blend` можно сохранить со сжатием: галочка Compress при сохранении или
  `bpy.ops.wm.save_as_mainfile(filepath=..., compress=True)`. Так сохранён
  `garmin-540-case-v5.blend`.
- Файл всё равно больше 100 МиБ — не коммитить и спросить, что делать:
  уменьшить сетку или завести Git LFS.

## Пуш и пулл-реквест

- `git push`, `gh pr create`, мерж, удаление веток и всё, что переписывает
  историю, — только после явного «да» на конкретную команду. Мержим, только
  когда об этом попросили.
- Тело PR — что поменялось и почему именно так. Для геометрии — с цифрами:
  какой зазор остался, что упёрлось в стенку, почему выбран такой размер.
- Подписи инструмента в PR не идут: ни «Generated with…», ни соавторства —
  то же правило, что и для коммитов.
- CI в репозитории нет: проверка — ваши расчёты и рендер.

## Перед тем как звать на ревью

Правка меняет посадку (полость, толщину стенки, окна) — скажите об этом
прямо и предложите напечатать пробу до серии. Расчётная проверка посадки —
ещё не примерка.
